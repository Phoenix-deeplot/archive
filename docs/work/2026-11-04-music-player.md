## 2. 规划（Claude）

### 现状（查过、量过）

- **来源**（`shelf-directory/listen.py`）：Apple、Deezer 每首只有 30 秒试听；整首的有 Audius、Jamendo（要 `JAMENDO_CLIENT_ID`）、网易云（要 `LISTEN_NETEASE_DIRECT=1`，用 `music.163.com/song/media/outer/url`，不是文档里的接口）。每首歌只有一个固定的 `audio` 地址，榜单生成时就定死。
- **慢**：一个榜单现场并发请求多个上游，最多等 6 秒；网易云榜单每次逐首 HEAD 检查 80 首；播放条只处理 `error`，音源卡住不报错就一直转圈。
- **标签**：`lpHTML` 一排标签，最多约 50 个（当天榜单、4 个地区热歌、3 个 Deezer 榜、20 个风格、动态歌单、网易云 13 个榜），榜单和风格混在一起。
- **行和字体**：`.ls-row`：封面 44px，歌名 14.5px 常规粗细，歌手 12px，右边圆形播放键和 ↗；列表标题 `h3` 用衬线字。
- **弹窗**（`plDlg`）：底部一排“清空列表 / 关闭播放器 / 完成”；“清空列表”会留着当前这首；倍速、定时关闭、列表都堆在弹窗里；“关闭播放器”只在这里。
- **波点接口**（小尘 API，实测）：搜索 0.4–0.9 秒；取详情 0.9–1.1 秒，返回 `play_url`（`http://car-er.kuwo.cn/<令牌>/<时间戳>/….flac`，会过期，https 也能通）和 `lrc`（带时间轴的歌词）；`bf` 音质参数无效，永远是整首无损 FLAC（实测 27–55 MB）；没有榜单和推荐接口；同一个站还有“抖音热歌榜”（65 首，字段 `id/title/album/artist/pic/lyric/url/mobileUrl`，1.3 秒）和“QQ&网易云聚合”（`type=playlist` 实测 25 秒超时，不用）。
- **Jamendo 的 API 条款**：免费档仅限非商业，广告收入算商业，要向 Jamendo 要授权（用户已决定保留，之后发邮件问）。Last.fm 的商业使用要先签协议，不用。

### 做什么（三条分支，前后端并行）

**F1 `claude/music-core`（前端，先合，只依赖现有接口）**

1. **候选音源**：每首歌有 `cands[]`；没有时把 `audio` 补成一个候选。`plLoad` 按顺序试：`error`、8 秒内没有 `canplay`（卡住）、或 `loadedmetadata` 后时长和 `dur` 相差超过 15%，都换下一个；全失败才提示“放不了”并给原站链接；今日榜单的歌保持“自动跳下一首”。
2. **预取**：当前这首播过一半（或最后 20 秒）时，隐藏的 `Audio` 预取下一首的开头。
3. **播放模式（只音乐）**：一个按钮循环：列表循环 → 单曲循环 → 随机 → 顺序（播完停）；记在 `LS`；播客仍是倍速、后退 15 秒 / 前进 30 秒。随机用“洗牌一遍再重洗”，不重复。
4. **弹窗改造**：
   - 去掉“完成”。顶栏：左 ⌄ 收起（只 `plDlg.close()`，不停播放），右 ⚙ 播放设置、× 关闭播放器（停止、收起、隐藏播放条，队列仍存着，下次点歌会接着用；只有“清空”才清掉）。
   - 点弹窗外面、点 ⌄、3 分钟没有点击 / 滚动 / 按键（`PL_POP_IDLE_MS=180000`）都收起；和现有“暂停 5 分钟后收起播放条”并存。
   - 内容：当前这首、进度、控制条（播放模式 / 上一首 / 播放 / 下一首）、[队列 | 歌词] 切换、队列列表。没有歌词的歌，“歌词”这一格不显示。
   - 队列标题右边“清空”：全部清空（包括正在播的），收起弹窗、隐藏播放条，底部 toast“已清空 · 撤销”5 秒，撤销恢复队列和位置（不自动继续播放）。
   - ⚙ 设置只有 4 项（都有默认）：音源偏好（整首优先 / 速度优先 / 只用免费合规源）、手机流量下省流量（默认开）、定时关闭（关 / 15 / 30 / 60 分钟 / 播完这首）、显示歌词；底部一个“专注模式”入口和“清除这台设备上的听歌记录”。播客时多出倍速和前进后退。
5. **列表页**：一行 = 序号 / 封面 / 歌名 / 艺人 / ♥ / ⋯；去掉右边圆形播放键、↗、热度和来源文字（来源进“换音源”里）；点整行就播放；点歌 = 以这张列表为队列、从这首开始，“下一首播放”才插队；页头只有标题、数量、“播放全部”；去掉排序下拉和行 / 卡片切换（卡片留给精选歌单的货架）。
6. **字体和样式**：“听”的界面整个用系统无衬线（`--sans`），不加载新的网络字体；歌名 15–16px / 500，歌手 12–13px 次要色；行高 56–60，封面 44–48，圆角 6；分隔线从文字处开始（Apple Music 的样子）；序号 `tabular-nums`，前三名强调色；正在播放：歌名强调色 + 跳动条（替换序号）；可点区域不小于 44px。
7. **⋯ 歌曲菜单**（底部弹出）：下一首播放、加入歌单、喜欢、不想听这类（写入本机负反馈）；“找整首”“换音源”“下载”在 F1 先不显示（F2 接上）。

### 接口约定

后端新增字段都是**可缺省**的（旧页面忽略），`/api/listen` 现有字段不变。以这里为准；改动先改这里并通知另一方。

```
GET /api/listen?lang=zh|en&region=auto|cn|global
  -> { date, updated, lang, region: 'cn'|'global',
       groups: [{ id, name, name_en, kind: 'daily'|'chart'|'list'|'style'|'scene', type: 'music'|'podcast', net,
                  region?: 'cn'|'jp-kr'|'west'|'global', cover?, n? }] }

GET /api/listen?g=<id>&lang=&region=
  -> 现有字段；每首歌新增:
     { id, title, artist, cover, dur, hot?, lang?, market?: 'cn'|'jp-kr'|'west'|'global', tags?: [..],
       cands?: [{ p: 'netease'|'bodian'|'audius'|'jamendo'|'apple'|'deezer',
                  k: 'full'|'preview'|'embed'|'link',
                  audio?, embed?, url?, net: 'cn'|'global'|'any',
                  big?: true, size?: bytes, dl?: true, lyr?: true, lic?: '...' }],
       audio (兼容：第一个可直接播的地址), preview? }

GET /api/listen?resolve=1&id=<song id>&t=<title>&a=<artist>&d=<seconds>
  -> { ok, ttl, cands: [...同上，地址是新鲜的], lyrics?: { fmt: 'lrc'|'text', text, from } }

GET /api/listen?search=<q>&lang=
  -> { ok, partial?, items: [同一首合并后的歌，cands 带各家] }       (最多等 3 秒，部分结果也返回)

GET /api/listen?pool=<cn|global>
  -> { updated, stale?, items: [{ id, title, artist, cover, dur, rank, market, tags, from }] }   (推荐用；不含个人信息)

GET /api/listen?diag=1
  -> 现有字段 + providers: [{ id, ok, ms, err?, last_ok_at? }]
```

- 缓存：榜单 `s-maxage=1800, stale-while-revalidate`；`resolve` 60 秒；`search` 600 秒；`pool` 长缓存，上游失败返回最近一份（不超过 36 小时）并带 `stale: true`。
- 地址有时效：`resolve` 的结果前端最多留 `ttl` 秒；https 页面只收 https 地址（`http://` 的由后端改写成 `https://`，改写后 HEAD 通了才给）。
- 不接受任意 URL；参数长度限制；密钥只在服务端环境变量，不进仓库、不贴聊天。
- 环境变量开关：`LISTEN_BODIAN`（不设 = 开，`0` = 关）、`LISTEN_NETEASE_DIRECT=1`（现有）、`JAMENDO_CLIENT_ID`（现有）、`LISTEN_DISABLE`（现有）。**线上环境变量只由用户设置。**

### 风险和要避开的冲突点

- **版权和条款**：波点（小尘 API，非官方入口，接口自己写着“支持会员歌曲”）、网易云直连（`outer/url` 不是文档接口）、Jamendo（API 免费档不含广告站）。这是用户知道并决定的；每一项都有开关（`LISTEN_BODIAN=0`、不设 `LISTEN_NETEASE_DIRECT`、去掉 `JAMENDO_CLIENT_ID`），后端不代理音频；歌词随来源，来源关了歌词也关，歌词不存服务端。
- **流量**：波点给的是无损 FLAC（27–55 MB 一首），所以有 `big` 标记和手机流量保护；音质参数无效。
- **时效和混合内容**：播放地址带令牌会过期，只能播放时现取；https 页面不能放 http 地址。
- **单点**：小尘 API 是一个人维护的免费接口（累计调用几千次、没有 SLA，同一个站的聚合接口实测 25 秒超时），所以超时 ≤ 8 秒、连续失败熔断、永远有别的候选。
- **隐私**：画像只在本机、不上传；更新说明里“不记录你听了什么”那句要同步改。
- **冲突热点**：`index.html` 里 F1 只动 `pl*`、`lp*`、`ls*` 和这一块的 CSS；Codex 的热榜页函数不碰；新词只加新的一行 `Object.assign`。
- **现有测试**：`s_player`、`s_player2`、`s_listen`、`s_focus` 里有对“清空列表 / 关闭播放器 / 完成”按钮的检查，要跟着新弹窗改，不能删检查项了事。
