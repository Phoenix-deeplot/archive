### 接口约定

- 只调用既有目录服务：`GET /api/hot` 获取栏目和平台索引；`GET /api/hot?p=<platform>&format=json&n=50[&region=XX][&tr=zh]` 获取某榜单内容。
- 不改响应字段、不新增服务端接口；继续使用现有 `columns`、`platforms`、`items`、`updated`、`region` 等字段。
- 若列表项没有可靠日期或热度值，不推断跨平台绝对热度；显示来源榜单原名次与更新时间。

### 改动范围

1. `/hot/` 默认展现跨平台的“今日精选”内容流；用现有平台列表顺序与榜单条目顺序构建可解释的初始排序。
2. 推荐前过滤无标题/无有效链接项，按规范化链接和标题去重，并限制单一来源连续占满列表；跨平台名次只做榜内归一，不直接比较原始热度数值。
3. 在卡片上突出标题与摘要，保留来源平台、榜内名次、可用的热度/更新时间及站内阅读或原站跳转提示。
4. 把栏目、平台和地区选择收进“浏览平台榜单”区域；默认状态不要求用户操作这些筛选。用户仍可进入单个平台榜单、刷新、订阅。
5. 维持当前网站视觉系统、响应式和中英文界面；不改其他页面的导航结构。
6. 暂不提供周榜/月榜切换：现有接口没有可依赖的历史榜单快照。后续如需周期榜，先由服务端提供并验证历史数据。

### 验收

- 首次打开 `/hot/` 无需先选平台即可出现跨平台条目；空数据或接口失败有清楚的重试状态。
- 同一内容不重复，榜单来源不过度集中；缺少日期/热度字段时布局仍正常。
- 平台榜单展开后，原有栏目、平台、地区选择、单榜刷新、订阅及阅读/外跳行为可用。
- 手机端无需横向滚动一长串平台；桌面和移动端均能辨认标题、来源与名次。
- 检查内联 JavaScript 语法和热榜相关函数无重名；使用 Codex 端口范围 8900–8999 进行本地预览。
- 不合并、不推送、不部署。用户验收后再按要求处理合并。

### 端口

- claude：8800–8899、9440–9449；codex：8900–8999、9450–9459。

### 风险和要避开的冲突点

- 多平台混合首屏会增加首次请求数；实现需限制并发、复用 3 分钟缓存，并避免一次性加载所有平台的完整榜单。
- 部分榜单只有标题和外链，或源站无法内嵌；卡片必须如实标注跳转，不承诺全部站内阅读。
- 当前没有统一的来源质量分、用户兴趣画像或历史榜单快照；本次不伪造这些信号。以后要做个性化/周期榜需另定接口与数据方案。
- `index.html` 是大型单文件，只在热榜相关函数和样式中修改，避免翻译词典等冲突热点。
