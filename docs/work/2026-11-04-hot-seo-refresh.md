### 页面与搜索入口改动

1. `/hot/` 保留两个清晰入口：`今日精选` 与 `平台榜单`。不保留单独的“热点追踪”主 tab。
2. `今日精选` 首屏先展示热点追踪（最多 3 条、更新时间/来源数/原文入口），其下恢复跨平台今日推荐混合流。事件为空或接口失败时只隐藏/提示追踪区，不得连带隐藏今日推荐。
3. `平台榜单` 保留来源原始名次；按既有分类呈现，不比较跨平台原始热度值。移除用户指定的两段说明文案。
4. 修订 `/hot/` 的 title、description、H1、静态/无脚本摘要及站内可抓取链接，让页面明确描述“中文与海外平台热榜、今日精选、热点追踪”等真实功能。检查 canonical、robots、sitemap 与页面状态；避免堆砌 keywords 或生成低价值批量页面。
5. SEO 诊断包含站点内可验证的技术项；Search Console / Bing 的覆盖率、查询词、外链引用数据必须以站长后台为准。本次不宣称可直接解决排名、收录或外部引用少的问题。

### 接口约定

- 前端沿用既有 `GET /api/hot`（平台/榜单）及 `GET /api/hot/events?lang=zh&limit=...`（热点事件），不新增前端直连第三方服务，不改既有响应字段。
- 今日精选混合流继续复用 `/api/hot` 当前榜单结果；热点事件只作为首屏单独区块，不作为混合流唯一数据源。
- 第三方源的来源、失败状态、缓存策略在 shelf-directory 计划中约定；X/API 密钥只允许服务端环境变量，不进入仓库或浏览器。

### 风险和要避开的冲突点

- 目前前端把“今日精选排名”绑在事件接口结果上；事件为空会导致焦点模块消失。这次必须把今日推荐流与事件追踪解耦。
- 搜索引擎收录与引用受站外抓取、内容质量、搜索控制台状态影响；页面 meta 改动不是排名保证。
- 小红书、B 站和抖音已有后端定义，需先查线上返回状态而非重复添加；X 可能涉及付费 API 与平台条款；Polymarket 是预测市场数据，需清晰标注“市场概率/交易量，不是事实或投资建议”。

- `index.html` 是大单文件；限定修改热榜相关函数与 SEO 文案，避免翻译词典和其他功能。
