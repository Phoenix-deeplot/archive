## 2. 规划（Claude）

### 查到的原因

- **1、2 封面**：听歌服务的目录（`listen.py` 的 `/api/listen` 目录那一层）只给每个榜单 / 歌单 / 风格 / 场景 `id、name、kind、type、n、lang`，**没有 `cover`**；只有歌曲有封面。页面里写了“有 `cover` 就用”，但真实数据从来没有，所以全是彩色方块上写两个字。
- **4 主题**：是我上一轮的错。发现世界里我把手机上的“筛选面板”隐藏了，规则写成了 `body.in-dir .fl-panel{display:none!important}`，而主题小窗也用了 `fl-panel` 这个类，于是在发现世界里点 ◐ 弹不出来（我的书架里是好的）。改成只隐藏 `#flPanel`。已在预览里复现：`#themePop` 在发现世界里 `hidden=false` 但 `display:none`。
- **5 双列**：`.lp-rows` 为了“一列读下去”限了 `max-width:820px` 且一列；宽屏右边就空了。
- **6 弹窗**：`⋯` 的菜单（`#lsMenu`）和播放器弹窗共用 `dialog.plp`，那是贴底的抽屉（`margin:auto auto 0`，只有上面两个圆角）。

### P5 封面：三个做法（要用户选）

- **A. 页面自己画海报**（不改服务）：每张歌单 / 风格 / 场景卡片画成一张小海报：两种相近色的渐变（颜色由 id 算，同一张永远同色）、一个大的半透明图形（风格＝唱片圆环，场景＝月亮 / 太阳 / 山，歌单＝叠起来的方块）、名字写在左下角（白色粗体，最多两行）、右上角一个小图标。不需要网络，立刻有，好看程度可控。
- **B. 服务给封面**：让 `/api/listen` 的目录给每个榜单 / 歌单一个 `cover`（取歌单里第一首有封面的歌，或 Deezer 歌单自带的图）；这要改 shelf-directory 的 `listen.py`（Codex 在改的文件，要等他）并部署，部署之前页面上还是原样。风格 / 场景没有“第一首”的概念，仍要 A。
- **C. A + B**：先上 A，以后 B 好了，有 `cover` 的用图，没有的还是 A 的海报。

我的建议是 **C**，现在先做 A（不依赖谁）。给你看过一张示意图再定细节。
