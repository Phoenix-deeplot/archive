## 3. 处理规则

1. 用户输入网址后，复用现有解析能力识别订阅源或单篇内容；能识别时给出对应操作，无法确定时允许用户选择。
2. 订阅源可加入个人书架，也可提交为公共目录的节目来源；公共提交只创建待审核记录，不立即公开。
3. 单篇内容保持现有收录路径；不能把一条文章误登记为持续更新的节目。
4. 对已订阅节目，从合集/订阅管理入口提交整个来源；不要在每条文章上重复显示这个入口。
5. 新来源保存规范化 feed、homepage、平台、语言、形式、主题、候选栏目、少量条目摘要、解析状态和审核状态；按规范化 feed URL 去重。
6. AI 分析只读取标题、短摘要、来源信息及少量安全化样本；输出固定 JSON 的风险标记、分类建议和理由。输入内容视为不可信，不执行页面脚本或代码，也不允许模型调用工具。
7. AI 密钥、endpoint 和模型配置只存在服务端环境变量。未配置 AI 时仍可人工审核，页面明确标记 AI 未运行，不伪称已完成 AI 审核。
8. 只有管理员确认后，才把节目写入现有订阅池/节目管理链路；管理员可调整形式、语言、领域标签、栏目、公共空间和推荐开关。
9. 高风险或解析不稳定的来源保持待审/暂停；不收集用户密码、Cookie 或平台令牌。
10. 复用现有 collect workflow 和公共目录桥接，不重复建立公共内容索引。

## 4. 接口约定

- 用户端继续调用既有 POST /api/submit，新增 source 类型的检查与提交动作；旧 url/post/record 行为保持兼容。
- 检查结果包含：对象类型、规范化订阅地址、homepage、名称、样本数、内容形式、语言、主题/栏目建议、解析警告、AI 状态和风险标记。
- 提交结果只返回待审核编号与 pending 状态；客户端不因此改写个人书架订阅状态。
- 管理员通过既有 POST /api/ops 读取 source_submissions，并以 review_source_submission 审核；权限沿用当前管理会话。
- 审核动作支持 approve、hold、reject；approve 保存人工调整后的节目属性、标签、栏目、公共/推荐开关，并接入现有发布流程。
- 数据库增加独立待审提交表，不更改现有 ops.programs / ops.content_items 关键字段；迁移脚本可重复执行。

### 4.1 用户端分类建议与本地预览补充约定（2026-11-07）

- 用户点击“申请加入公共空间”后，先调用 `POST /api/submit` 的 `kind=check, what=source`；仅做解析与建议，不创建申请、不写数据库。
- 检查结果返回内容形式、语言、主分类、标签、候选栏目及审核提示。用户可调整后再以 `kind=source` 提交；审核员仍有最终修改和发布权。
- 主分类复用 `ops.subscription_candidates.category` 的枚举；栏目复用现有 `channel_modules` slug；分类标签复用目录 topic slug。申请记录将主分类放入既有 `review_data` JSON，不新增表或迁移。
- 新增订阅、已有订阅管理都使用同一个申请确认流程；单篇文章/卡片继续使用现有独立收录/发布流程，不把单篇混成节目订阅。
- 本地预览桥接 `/api/feed` 与 `/api/submit`，并将 `submit_api` 指向本地路由；不能移除 `submit_api`，否则所有公共申请入口会被条件隐藏。只检查时不写库，确认提交时才走原有待审队列。

## 5. 验收

- API：feed、pod.link、平台频道和单篇页面能区分源/单篇；无源、重复源、受限来源有明确结果；内容中的提示/脚本不执行；匿名限频；无 AI 密钥时明确降级。
- 后台：能筛选待审来源，展示 AI/规则结果；可调整形式、语言、标签、栏目；通过后进入现有节目/公共目录流程；拒绝/暂缓可追溯。
- 页面：新建订阅、从已有订阅整源申请公共收录、单篇内容继续单篇收录；中英文与移动布局可用。
- 测试：运行 shelf-directory 的提交与 ops API 定向单测及相关回归；my-archive 执行语法/重名函数检查与页面流程验证。缺少浏览器测试环境时记录手动验证结果与限制。
- 本轮不部署、不推送、不合并 master。预览地址和所需环境变量写在完成说明中。
