## 2. 规划（Claude）

### 查到的事实（2026-11-09 在开发电脑上实测）

- 线上 `adminbook.zhitree.cn/api/hot?p=polymarket` 返回 502（空体）。原因：现在用的 `gamma-api.polymarket.com/events?...&limit=50` 要 76–160 秒、约 8 MB（每个事件都带着完整的市场数据），超过 Vercel 函数的 10 秒；`agg.fetch` 的 3 MB 上限还会把 JSON 截断。
- 用户给的文档接口 `GET /events/keyset`（`order=volume24hr&closed=false&ascending=false&limit=20`）能排，但 31–59 秒、约 4 MB，文档写明“总是包含 Markets”，没有参数能瘦身；不加 `order` 返回的是 2021 年已关闭的旧事件。**不可行。**
- 同一家族的 `GET /markets/keyset?closed=false&order=volume24hr|volume1wk&ascending=false&limit=40`：约 3–4 秒、约 290 KB，可行。每个市场带着所属事件对象 `events[0]`（`slug`、`title`、事件自己的 `volume24hr` / `volume1wk`），日榜 / 周榜两种排序都支持。
- 知乎：`zhihu`（知乎热榜）现在在 `media`（影音与社区）栏，`zhihu_daily`（知乎日报）在 `news`（综合热点）栏。

### 接口约定

- `/api/hot?p=polymarket&format=json[&period=day|week]` 的返回形状不变（`items[].title / url / heat / note`，`period`）；变的是取数：一次 `markets/keyset`（`POLY_ORDER` = `volume24hr` 或 `volume1wk`，`limit=40`），按事件分组，每个事件用**事件自己的**成交量（`events[0].volume24hr` / `volume1wk`）重新排名，链接仍是 `https://polymarket.com/event/<事件 slug>`；`slug` 不合规的丢掉。
- 说明：只有在前 40 个市场里出现过的事件才会进榜（一个事件的所有市场都排不进前 40 的话它不在榜上）。
- 栏目：`zhihu` → `news`，`zhihu_daily` → `media`。两个榜的 id、名字、地址不变（页面里按 id 认，不受影响）。
