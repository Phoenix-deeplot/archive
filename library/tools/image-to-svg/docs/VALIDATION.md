### 仍然可见的限制

- 细线/镂空样例已从历史的 145 条 path 收敛为 4 条原生 path（2 条为稳定宽度 `stroke`），但原 PNG 是 Lanczos 抗锯齿，而浏览器 SVG 的边缘覆盖不同；Alpha SSIM `0.9594`，不能宣称 99% 恢复。
- JPEG 样例的压缩背景、色度变化和不透明 Alpha 使其最小分数只有 `0.9093`；它仅验证 JPG 输入与下载闭环，并不属于本 Demo 的高保真目标范围。
- 文本继续按轮廓处理，复杂照片、滤镜、网格渐变、多层半透明及复杂共享边界仍需要更专业的局部拟合 / 人工编辑流程。

## 执行方式

1. 在 `library/tools/image-to-svg/` 启动 `npm start`，页面位于 `http://127.0.0.1:4173`。
2. 使用真实 Chrome 无头页面依次将三份 PNG 和一份 JPEG fixture 赋给页面的上传控件。
3. 页面自身执行 ImageTracerJS 描摹、有限候选搜索、SVG Blob → 同尺寸 PNG Canvas 栅格化和 SSIM 选择。
4. 每个案例实际触发“下载 SVG”，并读取页面结构审计；浏览器控制台 `pageErrors=[]`。

该回归使用的是实际网页逻辑，不是调用独立的模拟转换器。可选脚本为 `scripts/run-browser-validation.js`；它需要 Playwright（Demo 运行本身不需要）。

## 历史审计

四份导出结果均显示：

- `image=0`
- `foreignObject=0`
- `data URI=0`
- 外链 URL `=0`
- 事件属性 `=0`
- `viewBox="0 0 256 256"`

每次测试还实际触发了下载，并将下载字节的 FNV-1a 指纹与页面最终 SVG 字符串的指纹比对：四例均匹配。这与实现中“预览 / 评分 / 下载均复用 `state.svgText` → 同一个 Blob”的约束一致。

渐变案例额外包含 `linearGradient=1`；另两个案例只含 path。页面下载按钮复用已审计、已评分的 SVG Blob。

## 历史不足与解释

- 少色 Logo 的轮廓已经压缩到 5 个 path，但 Raster→Bezier 与浏览器 SVG 光栅器的抗锯齿覆盖并不完全相同，因此 Alpha SSIM 未达到 0.99。
- 细线和小孔洞是本版本最弱的情况。Demo 已把它们保留为路径而没有把背景染白或嵌入 PNG；但 3 px 线条和孔洞边缘量化后仍造成明显 Alpha / 白底差异。
- 简单渐变成功转为 1 个 path + 原生 `linearGradient`，轮廓 F1=1；白底 SSIM 仍少 0.0016，说明两个颜色 stop 和亚像素边界不足以精确复刻该带抗锯齿的输入。

因此当时没有任何案例被标为“达到本 Demo 的图像相似度目标”。该状态符合当时 UI 的真实阈值策略，下载功能仍可用。
