# Browser tests (end to end)

Headless Edge, driven over the DevTools protocol (`cdp.js`, Node 22+, nothing to install), against a demo build of the page and a few fake services. Meant to be used by every agent that changes the page.

```
python -X utf8 devtools/e2e/make_demo.py            build the demo from this folder   (--src <folder> to test another worktree)
powershell -File devtools/e2e/rig.ps1                start the demo (8820), the fake services (8840–8850) and two browsers (9444, 9445)
node devtools/e2e/tests/s_listen.js                  run one test (it prints PASS / FAIL lines and "N passed, M failed")
powershell -File devtools/e2e/run_all.ps1            all of them, 25-40 minutes (start it detached; the result is in .rig/all.out, every line says how long the test took; at the end: how many new / known failing lines, and the five slowest)
powershell -File devtools/e2e/run_all.ps1 -Quick     the short list for every day, about 5 minutes (the whole list is for before a merge);  -Only a,b  just these;  -Skip a,b  without these
python -X utf8 devtools/e2e/books_preview.py         (set E2E_REAL_BOOKS=1 before rig.ps1 to let /api/book read the real chapters instead of the fake site) put the real picked books (shelf-directory's registry/books.json) into the demo directory, to look at them (a test that writes its own directory replaces them)
python -X utf8 devtools/e2e/dup_funcs.py             the page is ONE script: a function declared twice silently overrides the first (run it after every edit of index.html)
python -X utf8 devtools/e2e/syntax_check.py          the script of the page parses
```

- **Ports** default to 8820, 8840–8843, 8850, 9444 and 9445. The rig accepts `E2E_APP_PORT`, `E2E_HOT_PORT`, `E2E_FEED_PORT`, `E2E_TEXT_PORT`, `E2E_POD_PORT`, `E2E_READ_PORT`, `E2E_CDP_PORT` and `E2E_CDP2_PORT`; `run_branch.ps1` defaults to the Codex range (8920, 8940–8943, 8950, 9450–9451) so it can run beside Claude's rig. Two agents must still use separate values.
- `E2E_SRC` (the folder under test), `E2E_DIST` (the demo to open), `E2E_SHOTS` (where screenshots go), `SHELF_DIRECTORY` (the folder of the directory service, for the fake `/api/listen`): see `paths.js`.
- **Fixtures**: `fixtures/demo-library` (a made-up library; the guide of the project is added to it), `fixtures/site.demo.json`, `fixtures/directory.base.json` (the made-up public directory; `dir_fixture.js` writes the one most tests use into the demo and a test may change it: listen, focus and more leave it changed, so they run last).
- **The services** (`services/`) are plain Python: `sync_dev.py` (the directory service: sync store, hot lists, `/api/listen` as `shelf-directory/listen.py` answers, switchable with `/__listen?mode=ok|down|junk|empty|real`), `feed_site.py` (a made-up blog; written again, its titles are "<name> 第 N 篇"), `feed_site_text.py`, `podcast_site.py` (episodes that really play), `read_site.py`.
- **Not moved yet**: the tests that need the PDF conversion demo (`s_pdfconv`, `s_convert`), the admin page fakes (`s_admin_*`), `s_feed`. They need fixtures that were not kept.
- **Known to fail** (they need the original fixtures, which were not kept; the page is not at fault): the table `$known` in `run_all.ps1` (s_read: the log of the reading site, and a directory item it cannot find; s_reco: two checks of the rows of the recommended list; s_sync check B; s_mobile when a test before it counted something). `run_all.ps1` still runs these tests, writes their failing lines as `known (why)` and counts them apart from the new ones; take a row out of the table when it is fixed. Everything else passes.
- **Why it takes long**: tests used to wait a fixed time after every click (`sleep(500)`, about 940 seconds of it in all), the tests run one after the other (they share the fake services, the ports and the directory fixture), each one clears the browser and loads the page again, and the rig is restarted a few times. Look at the times in `.rig/all.out` before changing anything.
- **`settle.js`: wait for a quiet page instead of a fixed time**. `const settle = await require('../settle')(c);` once per file, then `await settle(2500)` where `await sleep(2500)` was: it returns as soon as the page and its frames (the reader's too) have not changed and no request has been on its way for about a fifth of that time (0.3-0.8 s), and never later than the time given; it never answers before that quiet time has passed. A request that has been on its way for more than 2 s (a held one, a hanging one) does not count. **Keep `sleep()` for what waits for a timer of its own** (a thanks that closes after a second, a debounce, a prefetch after 20 s): a quiet page is not a finished one then. `E2E_SETTLE_STATS=1` prints at the end how many waits went to the end; `=2` says why the first ones did (what kept the page busy). In the eight heaviest tests (s_sync, s_read, s_bookpaged, s_dir, s_shell, s_text, s_reco, s_rich) it brought the run from 11.8 to 5.8 minutes with the same results; the part of s_read / s_reco after the place where they stop (known failures) was not run, so it still has `sleep()`.
- **Dates**: `s_first` and `s_dir` freeze the clock of the page (`FREEZE_DAY`, `FREEZE_AT`): "today's three" take the entries of the last 72 hours and the fixture's newest entry is from 2026-10-24.
